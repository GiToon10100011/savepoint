# 기능 명세서

SavePoint는 게임을 **평가하고, 플레이 이력을 기록하고, 취향을 공유하는** 게임 아카이빙 서비스다. 왓챠피디아의 평가·리뷰·프로필·소셜 경험을 계승하고 게임 특화 기능(플레이 상태·진행도·엔딩 기록·기록 달력)을 더한다.

- 근거: [REA 개요](../rea/overview.md), [기능 분석](../rea/feature-analysis.md)
- 관련: [사용자 플로우](user-flows.md), [데이터 모델](../architecture/data-model.md), [아키텍처](../architecture/architecture.md)
- 우선순위: **모바일 웹 최우선**, PC는 반응형으로 지원한다.

## 1. 핵심 원칙

1. **평가 · 플레이 상태 · 리뷰는 서로 독립이다.** 하나를 바꿔도 다른 것이 자동으로 바뀌지 않는다.
2. 엔딩을 기록해도 평가나 리뷰를 자동 생성하지 않는다. 평가해도 엔딩을 본 것으로 처리하지 않는다.
3. 게임 메타데이터(`games`)와 사용자 기록(`user_games`, `game_ratings`, `game_reviews`)은 별개 데이터다.
4. 모든 입력 정보는 선택이다. **시스템이 자동 기록하는 값**과 **사용자가 직접 입력하는 값**을 구분한다.
5. 기록 비용을 최소화한다. 게임 상세 화면에서 추가·평가·상태 변경·날짜 기록을 모두 할 수 있어야 한다.

## 2. 범위

| 구분 | 포함 |
|---|---|
| **MVP** | 인증, 프로필, 게임 검색·IGDB 연동·수동 등록, 게임 상세, 평가, 라이브러리(상태·진행도·날짜·플랫폼·메모), 리뷰(공개/비공개·좋아요·정렬), 기록 달력(월간·일별·월 선택·월간 통계·연도별), 장르·태그, 게임회사(개발사/퍼블리셔·좋아하는 회사), 팔로우·팔로워·팔로잉, 소셜 피드(기본) |
| **후속** | 리뷰 댓글, 알림, 예상 별점·추천, 취향분석 전체, 컬렉션, 진행도 이력·체크리스트·챕터 방식, 플랫폼 보유 등록, 월말결산 화면, 다크 모드 완성도 개선 |
| **제외** | 앱 설치 유도, 광고, 매거진, 이벤트 |

## 3. 용어

| 용어 | 정의 |
|---|---|
| 평가 | 게임에 남기는 별점(0.5–5.0, 0.5 단위). 저장값은 정수 1–10 |
| 플레이 상태 | 라이브러리에 등록한 게임의 상태. 7가지 |
| 리뷰 | 게임에 남기는 글. 평가와 별개로 작성·삭제한다 |
| 라이브러리 | 사용자가 등록한 게임의 개인 목록(`user_games`) |
| 이벤트 | 달력·피드에 표시되는 기록 단위(`game_play_events`) |

## 4. 기능 명세

### A. 인증·프로필

| ID | 기능 | 규칙 |
|---|---|---|
| A1 | 가입·로그인·로그아웃 | 이메일/비밀번호와 Google. 비로그인 사용자가 보호 경로에 접근하면 로그인으로 보내고 로그인 후 원래 경로로 돌려보낸다(REA F17) |
| A2 | 프로필 생성 | 첫 로그인 시 `handle`(영문 소문자·숫자·`_`, 3–20자, 유일), `nickname`(1–20자)을 만든다 |
| A3 | 프로필 수정 | 닉네임·자기소개(200자)·아바타. 본인만 수정한다 |

수락 기준: 새로고침 후 세션이 유지된다 · 비로그인 상태에서 쓰기 동작은 모두 거부된다 · 잘못된 비밀번호는 구체적인 오류 문구를 보여준다.

### B. 게임 메타데이터·검색

| ID | 기능 | 규칙 |
|---|---|---|
| B1 | 게임 검색 | 서버에서 처리한다. 내부 DB를 먼저 조회하고 결과가 부족하면 IGDB를 조회해 후보를 보여준다(읽기 전용, 비로그인 가능). 가져오지 않은 후보는 `/games/igdb-{id}` 미리보기로 열리고, 로그인한 사용자가 처음 기록할 때 내부 DB로 가져온다. 20건씩 페이지네이션 |
| B2 | 검색 UI | 입력 + `취소`. 빈 상태는 인기 게임(평가 수 기준), 결과 탭 `게임 / 회사 / 유저`, 결과 없음 문구와 **수동 등록** 진입점 |
| B3 | 수동 등록 | 제목(필수), 출시일·플랫폼·장르·태그·개발사·퍼블리셔·소개·커버(선택). 등록자가 수정하고 다른 사용자는 읽기만 한다 |
| B4 | 외부 API 장애 | IGDB 호출이 실패해도 내부 DB 검색과 수동 등록은 동작한다 |

### C. 게임 상세

표시 항목: 커버(원본 비율 유지), 게임명(한국어 제목이 있으면 우선), 출시일, 개발사, 퍼블리셔, 플랫폼, 장르, 태그, 소개, 평균 평점·평가 수, 리뷰 목록, 관련 게임, **내 플레이 상태·진행도·평가·리뷰**.

- 장르·태그·회사 이름은 링크이며 해당 목록으로 이동한다(B/H/I).
- 내 기록 영역에서 라이브러리 추가, 상태 변경, 진행도 변경, 날짜 기록, 평가, 리뷰 작성을 모두 할 수 있다.

### D. 평가

| ID | 기능 | 규칙 |
|---|---|---|
| D1 | 등록·수정 | 별 5개, 0.5 단위. 탭·키보드로 선택하면 **즉시 저장**한다. 이미 있으면 값을 바꾼다 |
| D2 | 취소 | 명시적 `평가 취소` 버튼으로 삭제한다 (REA의 같은 별 재탭 취소는 보조 동작으로 허용) |
| D3 | 중복 방지 | 사용자당 게임당 1개(`unique`) |
| D4 | 표시 | 미평가는 외곽선 별, 평가는 채움 별과 숫자. 평균 평점·평가 수는 `4.2 (1,234)` 형식 |
| D5 | 목록 | `/u/{handle}/ratings`에서 평가한 게임 목록. 최신순·평점순 |

수락 기준: 평가해도 라이브러리·상태가 바뀌지 않는다 · 취소하면 평균·평가 수가 원복된다 · 다른 사용자의 평가는 수정할 수 없다.

### E. 라이브러리

**상태 7가지**: 관심 있음 · 플레이 예정 · 플레이 중 · 일시 중단 · 엔딩 완료 · 100% 달성 · 플레이 포기. 사용자가 직접 바꾸며 **전환 순서를 강제하지 않는다**(플레이 예정 → 엔딩 완료 가능). 상태도 선택 입력이라 **지정하지 않고 등록할 수 있다**(`상태 미지정`, `전체` 목록에서 확인). 이 경우 `user_games.status`는 NULL이다.

| 필드 | 입력 주체 | 비고 |
|---|---|---|
| 게임 등록일 | 시스템 | 라이브러리에 추가한 시각 |
| 마지막 플레이일 | 시스템(진행도·플레이 기록 변경 시) + 수동 수정 | |
| 플레이 시작일 · 엔딩 달성일 · 100% 달성일 | 사용자 | 상태 시트에서 입력. 오늘 날짜를 기본값으로 제안하되 사용자가 확정한 값만 저장한다 |
| 플레이 상태 · 플랫폼 · 플레이 시간 · 진행도 | 사용자 | 모두 선택 |
| 개인 메모 | 사용자 | **본인에게만 보인다** |
| 평가 여부 · 리뷰 여부 | 계산값 | 저장하지 않고 조인으로 계산한다 |

**진행도**: 초기 버전은 `퍼센트(0–100)`와 `텍스트(예: "챕터 3 진행 중")`를 지원한다. `progress_kind`로 챕터·체크리스트 확장 여지를 둔다. 변경 이력은 후속.

**목록**: 탭/필터 `전체 · 플레이 중 · 플레이 예정 · 엔딩 완료 · 100% 달성 · 평가함 · 리뷰 작성함`. 정렬 `최근 등록 · 최근 플레이 · 엔딩 달성일 · 평점 · 가나다`. 추가 필터 장르·플랫폼·상태. 커서 기반 페이지네이션.

수락 기준: 같은 게임을 두 번 등록할 수 없다 · 상태를 바꿔도 평가·리뷰가 생기지 않는다 · 엔딩 달성일을 기록해도 평가는 자동 생성되지 않는다 · 라이브러리에서 삭제해도 평가·리뷰는 남는다.

### F. 리뷰

| ID | 기능 | 규칙 |
|---|---|---|
| F1 | 작성·수정·삭제 | 평가 없이도 작성할 수 있다(독립). 사용자당 게임당 1개. 본문 1–5,000자, 스포일러 표시 선택 |
| F2 | 공개 범위 | `공개` / `비공개`. 비공개는 작성자만 본다 |
| F3 | 목록 | 게임 상세 하단. 정렬 `좋아요 순(기본) · 최신순`, 필터 `전체 · 팔로잉`. 카드에 작성자·작성일·평가(있을 때)·좋아요 수 |
| F4 | 좋아요 | 사용자당 리뷰당 1회 토글. 자기 리뷰에는 누를 수 없다 |
| F5 | 프로필 | `/u/{handle}/reviews`에서 작성한 공개 리뷰 목록 |

수락 기준: 리뷰를 삭제해도 평가는 유지된다 · 평가를 취소해도 리뷰는 유지된다 · 비공개 리뷰는 타인의 목록·피드·카운트에 나타나지 않는다.

### G. 기록 달력

이벤트 6종: **플레이 시작 · 엔딩 달성 · 100% 달성 · 리뷰 작성 · 게임 평가 · 플레이 기록**(+ 피드용 `라이브러리 등록`).

| ID | 기능 | 규칙 |
|---|---|---|
| G1 | 월간 달력 | 7열 격자. 날짜 칸에 이벤트 종류 아이콘과 개수를 표시한다. 이전/다음 달 이동, `이번 달` |
| G2 | 날짜 선택 | 칸을 선택하면 날짜별 기록 목록(일별 상세)으로 이동한다. 목록 행은 커버 썸네일·게임명·이벤트 레이블 |
| G3 | 게임으로 이동 | 목록의 이벤트를 선택하면 해당 게임 상세로 이동한다 |
| G4 | 월 선택 | 월 제목을 누르면 연도·월 선택 시트 |
| G5 | 연도별 조회 | 12개월 목록에 월별 이벤트 수. 월을 선택하면 해당 월 달력 |
| G6 | 기간별 엔딩 | 이벤트 종류와 기간(시작일~종료일)을 정해 엔딩·100% 기록을 목록으로 본다 |
| G7 | 월간 통계 | 시작·엔딩·100%·리뷰·평가 건수와 플레이 시간 합 |
| G8 | 필터 | 이벤트 종류 칩. 선택 상태는 URL 쿼리에 반영한다 |
| G9 | 기록 추가 | 일별 기록 화면 하단의 두 버튼. `플레이 기록 추가`는 선택한 날짜로 고정해 라이브러리의 게임·플레이 시간·메모를 입력한다(`play_session`). `게임 추가하기`는 검색해 라이브러리에 등록하고 시작일을 그 날짜로 채운 상태 시트를 연다 |

- **이벤트 구분은 색에만 의존하지 않는다.** 아이콘(글리프) + 텍스트 레이블을 함께 쓰고, 색은 채도를 낮춘 보조 수단으로 더한다. 색은 디자인 토큰(`--event-*`)으로 분리돼 있어 바꿀 수 있다.
- 달력은 필요한 **한 달 범위의 이벤트만** 조회한다.
- 달력 이벤트는 `user_games`의 날짜(시작·엔딩·100%)와 평가·리뷰 생성에서 자동으로 만들어지고, 플레이 기록만 사용자가 직접 추가한다.

수락 기준: 시작일을 기록하면 해당 날짜에 `플레이 시작`이 나타난다 · 날짜를 지우면 이벤트도 사라진다 · 비공개 리뷰 이벤트는 본인 달력에만 보인다 · 키보드로 날짜를 탐색할 수 있다.

### H. 장르·태그

- **장르**는 게임의 기본 분류, **태그**는 세부 특징이다. 서로 다른 테이블이다.
- 시드 장르: RPG, JRPG, 액션, 어드벤처, FPS, TPS, 로그라이크, 전략, 시뮬레이션, 퍼즐, 레이싱, 스포츠, 비주얼 노벨, 소울라이크, 오픈 월드. 태그 예: 턴제, 파티 기반, 스토리 중심, 일본풍, 싱글 플레이.
- 태그/장르를 선택하면 해당 게임 목록(`/tags/{slug}`, `/genres/{slug}`)으로 이동한다. 20건씩 페이지네이션.

### I. 게임회사

- 회사는 게임과 별도 데이터다. **개발사와 퍼블리셔를 구분**하며 한 게임이 여러 회사와 연결된다.
- 회사 검색, 회사 상세(`/companies/{slug}`: 개발한 게임 / 퍼블리싱한 게임), 좋아하는 회사 추가·삭제(최대 20개), 프로필에 표시.
- 회사가 없으면 사용자가 등록할 수 있다.

### J. 소셜

| ID | 기능 | 규칙 |
|---|---|---|
| J1 | 팔로우·언팔로우 | 중복 불가, 자기 자신 불가. 프로필·목록에서 토글 |
| J2 | 팔로워·팔로잉 목록 | 사용자 행마다 팔로우 상태 버튼 |
| J3 | 사용자 검색 | 닉네임·handle |
| J4 | 피드 | 팔로우한 사용자의 활동: 평가, 리뷰, 엔딩, 100%, 라이브러리 등록. 같은 사용자의 같은 종류 활동을 짧은 시간 안에 묶어 표시한다. 탭 `팔로잉 / 내 활동`. 커서 기반 20건씩 |

수락 기준: 비공개 리뷰 활동은 피드에 나타나지 않는다 · 팔로우를 끊으면 이후 피드에서 사라진다.

### K. 프로필

본인과 타인 화면이 다르다.

- 공통: 아바타·닉네임·자기소개, 팔로워·팔로잉 수, **평가한 게임 수 · 리뷰 수 · 엔딩 완료 수 · 100% 달성 수**, 좋아하는 게임회사, 최근 평가한 게임, 최근 리뷰, 최근 플레이 기록.
- 본인: `프로필 수정`, 개인 메모 접근, 비공개 리뷰 포함.
- 타인: `팔로우` 버튼, 공개 정보만.
- 통계 수치는 IBM Plex Mono로 표시하고 그래프·장식 시각화는 쓰지 않는다.

## 5. 독립성 검증 시나리오

| 상황 | 플레이 상태 | 평가 | 리뷰 |
|---|---|---|---|
| 플레이 중이지만 아직 평가하지 않음 | 플레이 중 | 없음 | 없음 |
| 엔딩을 봤지만 평가하지 않음 | 엔딩 완료 | 없음 | 없음 |
| 엔딩을 본 뒤 평가함 | 엔딩 완료 | 있음 | 선택 |
| 플레이하지 않았지만 기대작으로 등록 | 관심 있음 | 없음 | 없음 |
| 평가했지만 아직 플레이하지 않음 | (라이브러리에 없음 또는 플레이 예정) | 있음 | 선택 |

마지막 행은 라이브러리에 등록하지 않은 게임도 평가할 수 있어야 함을 뜻한다.

## 6. 비기능 요구

| 영역 | 요구 |
|---|---|
| 성능 | 검색은 서버에서 처리·페이지네이션. 달력은 한 달 범위만 조회. 피드·목록은 커서 방식. 커버는 `next/image`로 최적화 |
| 무결성 | 사용자별 평가·라이브러리·리뷰 중복 방지, 팔로우 중복·자기 팔로우 방지, 리뷰 좋아요 중복 방지, 소유자만 수정(서버 인가 + RLS) |
| 접근성 | 평가는 키보드로 조작, 달력은 키보드로 날짜 탐색, 이벤트는 색 외 단서 제공, 터치 영역 44px 이상, 모든 버튼에 접근 가능한 이름 |
| 반응형 | 모바일 우선. 단일/2열 그리드 → 3–4열 → 4–6열. 데스크톱은 최대 폭 제한 |
| 디자인 | StudioBlank Design System 준수(모노크롬, 직각, 그림자 없음). 이미지 위에 텍스트를 올리지 않는다 |
| 언어 | UI는 한국어. 게임명은 한국어 제목이 있으면 우선하고 없으면 원제를 쓴다 |

## 7. 결정 사항 (REA로 정할 수 없었던 것)

| 질문 | 결정 | 이유 |
|---|---|---|
| 리뷰 작성에 평가가 필요한가 | **불필요** | REA로 확인 불가. 요구사항이 "별점만, 리뷰 없이도 가능"과 "평가와 별개"를 요구한다 |
| 한 사용자가 한 게임에 쓸 수 있는 리뷰 수 | **1개** | 목록·피드·통계 단순화. 수정으로 갱신한다 |
| 평가 취소 방식 | **명시적 버튼** + 같은 별 재탭(보조) | 접근성, 숨은 동작 방지 |
| 라이브러리에 없는 게임의 평가 | **허용** | 평가와 플레이 상태는 독립 |
| 라이브러리 삭제 시 평가·리뷰 | **유지** | 독립 원칙. 라이브러리 유래 이벤트와 플레이 기록만 삭제 |
| 개인 메모 공개 여부 | **비공개 고정** | 개인 기록. 별도 테이블로 분리해 RLS로 보호 |
| 플랫폼 로그인 | 이메일, Google | Neon Auth가 지원하는 범위. 카카오는 후속 검토 |
| 달력 이벤트 색 | **채도를 낮춘 색 + 글리프·레이블**(사용자 선택 2026-11-11). 인터페이스 전반은 모노크롬을 유지하고 이벤트만 색을 쓴다 | `/dev/ui`에서 모노크롬 안과 색 안을 나란히 비교해 색 안으로 확정했다. 색만으로 구분하지 않으며(6종의 모양이 모두 다르다), 카드 배경 위 대비 3:1 이상을 테스트가 지킨다 |
