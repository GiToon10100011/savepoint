# UI 패턴 분석

왓챠피디아 모바일 웹에서 관찰한 **패턴과 정보 구조**를 정리한다. 색·형태를 복제하려는 것이 아니며, 각 항목 끝의 "SavePoint 적용"이 StudioBlank Design System과 충돌하는 부분을 어떻게 풀지 적는다.

## 1. 레이아웃 기본

| 항목 | 관찰 | SavePoint 적용 |
|---|---|---|
| 뷰포트 | 390px 기준 단일 열. 가로 여백 약 15–20px | 16px 좌우 여백, `md` 이상에서 최대 폭 제한 |
| 스크롤 | 문서 스크롤. 상단 헤더와 하단 내비는 고정, 목록은 가로 레일 + 세로 스택 | 동일. 라이브러리·달력은 정보 밀도를 우선 |
| 페이지 이동 | SPA. 상세·하위 화면은 좌상단 뒤로가기 | 동일 |
| 상태의 URL 반영 | 필터(`?content_type=`), 검색(`?query=&category=`), 월(`/2026/11`)이 URL에 들어간다 | 동일. 공유·새로고침에 안전 |

## 2. 하단 내비게이션

- 로그인 전 `홈 / 검색 / 로그인`, 로그인 후 `홈 / 검색 / 캘린더 / 피드 / 나의 왓챠`.
- 아이콘 위, 라벨 아래. **활성 탭은 아이콘이 채워지고 라벨이 굵어지며 색이 진해진다**(비활성은 회색 외곽선).
- 상세 화면에서도 내비가 유지된다(몰입이 필요한 화면에서도 숨기지 않음).
- SavePoint 적용: `홈 / 검색 / 라이브러리 / 달력 / 프로필` 5탭을 제안하고, 피드는 홈 상단 탭으로 둔다(확정은 user-flows). 활성 표시는 채움·굵기 같은 비색상 단서를 쓴다.

## 3. 상단 헤더·검색

- 홈은 카테고리 탭(홈·영화·시리즈·책·웹툰), 검색 화면은 입력창 + `취소`.
- 입력창에 `clear`(×) 버튼. 입력 중에도 하단 내비는 보인다.
- SavePoint 적용: 홈은 탭 대신 로고 + 검색 진입점. 검색 화면은 동일한 입력 + `취소`.

## 4. 카드

| 유형 | 관찰 | SavePoint 적용 |
|---|---|---|
| 포스터 카드 | 포스터 위에 순위 숫자 오버레이, 아래에 제목·평균·메타 | 이미지 아래에 모든 텍스트를 둔다(StudioBlank: 이미지 위 텍스트 금지). 순위는 카드 옆 숫자로 |
| 히어로 카드 | 블러 처리한 배경 위에 라벨·제목을 올림 | 이미지 위 텍스트를 쓰지 않으므로 이미지와 정보를 위아래로 분리 |
| 목록 행 | 포스터 썸네일 + 제목 + `유형 · 연도` + ★ 점수 + `…` 메뉴 | 행 높이 48px 규칙은 라이브러리·달력 상세처럼 밀도가 필요한 곳에서 썸네일 행으로 예외 처리 |
| 코멘트 카드 | 작성자·날짜·점수·본문(제목 링크)·좋아요 요약 | 그대로, 점수는 사각 칩으로 |

## 5. 평가 UI

- 별 5개 SVG(각 44×44px, 총 폭 220px, 화면 가운데). 탭 영역이 곧 별 크기이므로 모바일 터치 크기(44px)를 충족한다.
- 상태: 미평가(회색 외곽 없는 채움) → 평가(노란 채움, 반별은 좌측 절반만 채움).
- 별은 이름 없는 SVG라서 **스크린리더용 이름·값이 없다**(관찰된 접근성 결함).
- SavePoint 적용: 흑백 별(채움 = 검정, 비어 있음 = 외곽선). `role="slider"` + `aria-valuenow/min/max`(0.5–5), 방향키·Home/End 조작, 별과 별 사이 반 칸 터치, 명시적 `평가 취소` 버튼.

## 6. 액션 행

- 별 아래에 아이콘 + 라벨 4개를 균등 분할(`보고싶어요 / 코멘트 / 보는 중 / 더보기`). 꺼짐 = 회색, 켜짐 = 강조 색.
- 즉시 토글이며 켜졌다는 안내(토스트)가 없다 — 색만으로 상태를 전달한다.
- SavePoint 적용: 상태가 7가지라 토글 대신 **현재 상태를 보여주는 단일 버튼 → 상태 선택 시트**로 바꾼다. 켜짐 표시는 색이 아니라 라벨 텍스트 + 채움으로 한다.

## 7. 칩(필터)

- 캘린더 도메인 칩 `전체 / 영화 / 시리즈 / 책`: **선택 = 검정 배경 + 흰 글씨, 비선택 = 흰 배경 + 테두리**. StudioBlank 칩과 거의 같다.
- 선택은 URL에 반영된다.

## 8. 바텀시트·모달

| 시트 | 구성 |
|---|---|
| 본 날짜 변경 | 제목, 월 달력, 닫기(`close`) 버튼 |
| 캘린더 날짜 변경 | 제목, 연도, 12개월 격자, `완료` |
| 앱 설치 모달 | 로고, 안내 문구, 주 버튼(검정) + 보조 버튼(회색) |

공통: 어두운 배경 위에 아래에서 올라오는 시트, 닫기 버튼 또는 `완료`로 닫힘. SavePoint 적용: 사각형 시트, 배경은 반투명 검정, 모션은 200ms 이하의 단순 슬라이드(또는 없음). 오버레이는 사용자가 연 것만 허용하고 자동 노출(광고·앱 유도)은 하지 않는다.

## 9. 캘린더 격자

- 7열 격자, 요일 헤더(일~토), 오늘만 강조 색, 미래 날짜는 흐린 회색.
- 평가한 날은 포스터 썸네일이 칸을 채우고 우상단에 개수 배지(2건 이상).
- 날짜 칸은 `button`이며 이름이 `YYYY-MM-DD`다(스크린리더가 읽을 수 있음).
- 하단 우측에 원형 `+` 플로팅 버튼.
- SavePoint 적용: 칸 안에는 **이벤트 종류 아이콘 + 개수**를 기본으로 하고, 커버 썸네일은 선택한 날의 상세 목록에서 보여 가독성을 지킨다. 오늘 강조는 검정 외곽선, 이벤트는 색이 아닌 아이콘·패턴·텍스트로 구분한다. `role="grid"` + 방향키 탐색. 둥근 `+` 버튼은 사각형 버튼으로 바꾼다.

## 10. 목록·빈 상태·카피

- 빈 상태는 항상 **한 줄 안내 + 다음 행동 버튼**이다. 예: "아직 컬렉션이 없어요 / 첫 컬렉션을 만들어보세요." + `컬렉션 추가하기`.
- 오류·결과 없음: "검색 결과가 없어요. 다른 검색어를 입력해보세요."
- 격려 문구는 수량 구간마다 바뀐다("이제 조금씩 취향의 윤곽이 드러납니다."). 장식 없이 텍스트 한 줄이다.
- 숫자 표기: 날짜 `YY.MM.DD`, 상대 시간(`18시간 전`, `어제`), 큰 수 `227.9K`.
- SavePoint 적용: 빈 상태·결과 없음 패턴을 그대로 쓴다. 격려 문구는 후속 개선으로 미룬다.

## 11. 고정 하단 CTA

일별 상세에 `작품 추가하기`(검정 전폭 사각 버튼)가 하단 내비 바로 위에 고정된다. SavePoint 적용: 달력 일별 상세와 라이브러리에 같은 패턴(`게임 추가하기`)을 쓴다.

## 12. 상호작용 규칙 요약

| 규칙 | 관찰 |
|---|---|
| 저장 방식 | 토글·별점은 즉시 저장, 확인 대화상자 없음 |
| 취소 방식 | 별은 같은 값 재탭, 토글은 재탭 |
| 로그인 장벽 | 읽기 일부(코멘트 전체 목록, 추천)는 로그인 필요, 쓰기는 모두 로그인 필요. 이동 후 원래 경로로 복귀 |

## 13. StudioBlank와의 충돌 정리

| 왓챠피디아 관찰 | SavePoint 결정 |
|---|---|
| 분홍 강조 색(`rgb(255,47,110)`) | 사용하지 않음. 상태 강조는 검정·채움·굵기로 |
| 둥근 카드·버튼·아바타·칩(대부분 라운드) | 모든 radius 0 |
| 그림자·블러 배경(히어로, 시트) | 그림자·블러 금지, 평면 배경과 구분선 |
| 이미지 위 텍스트(히어로, 순위) | 이미지 아래에 텍스트 배치 |
| 이미지가 들어간 빈 상태·배너(결과 없음, 월말결산 배너) | 텍스트 + 단순 아이콘만 |
| 앱 유도·광고 오버레이 | 제외 |
