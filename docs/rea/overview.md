# 왓챠피디아 모바일 웹 REA — 개요

- 분석 대상: https://pedia.watcha.com/ko (공식 웹사이트, 모바일 웹)
- 수행일: 2026-11-10
- 목적: 왓챠피디아의 평가·기록·소셜 UX와 정보 구조를 분석해 게임 서비스(SavePoint)에 적용할 기능을 결정한다.
- 범위: **모바일 웹만**. 디자인 복제가 아니라 UX 패턴과 정보 구조 분석이 목적이다.

관련 문서: [page-analysis](page-analysis.md) · [feature-analysis](feature-analysis.md) · [ui-patterns](ui-patterns.md) · [reference-screenshots](reference-screenshots.md)

## 1. 분석 방법

| 항목 | 내용 |
|---|---|
| 도구 | Playwright 1.65 + Chromium(headless). 사용자 화면에 창을 띄우지 않는다 |
| 기기 에뮬레이션 | iPhone 14 프로필: 뷰포트 390×664 CSS px, DPR 3, 모바일 Safari UA, 터치, `ko-KR` |
| 수집물 | 페이지별 접근성 트리(aria snapshot), 스크린샷(CSS 스케일), XHR/fetch 요청 목록 |
| 요청 기록 | 엔드포인트·메서드·상태·요청 본문의 키 구조만 기록. 토큰·쿠키 값은 기록하지 않는다 |
| 로그인 | 사용자가 본인 계정으로 직접 로그인했다. 비밀번호는 다루지 않았고 세션 파일은 저장소 밖에만 둔다 |

## 2. 확인 수준 정의

| 표기 | 의미 |
|---|---|
| 실제 확인 | 브라우저에서 직접 화면·동작·네트워크 요청을 관찰했다 |
| 부분 확인 | 화면 일부 또는 일부 동작만 관찰했다. 확인하지 못한 부분은 본문에 "추정"으로 따로 적는다 |
| 미확인 | 접근하지 못했거나 실행하지 않았다. 구현된 것으로 가정하지 않는다 |

## 3. 수행한 쓰기 동작과 원복

사용자 계정에 대해 **되돌릴 수 있는 동작만** 실행했고, 매번 원복을 확인했다.

| 동작 | 결과 | 원복 확인 |
|---|---|---|
| 미평가 작품에 3.5점 등록 → 같은 별 재탭으로 취소 (2회) | `POST` / `DELETE` 확인 | 새로고침 후 "수정" 버튼 없음, 캘린더 월 평가 수 3 → 3 |
| `보고싶어요` 켜기 → 끄기 | `POST` / `DELETE` 확인 | 새로고침 후 버튼 색 원복 |
| `보는 중` 켜기 → 끄기 | `POST` / `DELETE` 확인 | 새로고침 후 버튼 색 원복 |

실행하지 않은 것: 코멘트·댓글 제출, 팔로우/언팔로우, 설정 변경, 컬렉션 생성, 다른 별점으로의 값 변경, 날짜 변경 저장.

| 8 | 팔로워·팔로잉 | 목록 화면. 팔로우 동작은 실행하지 않음 | 부분 확인 |

## 5. 핵심 발견

1. **평가**는 별 5개, 0.5점 단위이며 정수 `별점×2`(3.5 → 7)로 저장된다. 탭 즉시 저장되고, 같은 별을 다시 탭하면 취소(`DELETE`)된다.
2. **평가 / 보고싶어요 / 보는 중**은 각각 별도의 API 리소스(`/ratings`, `/wish`, `/doing`)로 호출된다. 한 동작이 다른 상태를 바꾸는지(독립성)는 상태를 함께 켜 본 적이 없어 **미확인**이다.
3. 평가하면 **본 날짜(기본값: 오늘)**가 함께 표시되고 "수정"으로 바꿀 수 있다. 이 날짜가 캘린더의 기준일일 가능성이 크지만, 본 날짜를 바꿔 확인하지는 않았다(추정).
4. **캘린더는 이 서비스의 핵심 화면**이다. 일 단위 격자에 작품 포스터가 올라가고, 날짜를 탭하면 일별 상세로 이동하며, 월 선택 시트와 월말결산이 있다.
5. 로그인 후 하단 내비는 **홈 / 검색 / 캘린더 / 피드 / 나의 왓챠** 5탭이다. 비로그인은 3탭(홈·검색·로그인)이다.
6. **코멘트(리뷰)**는 별점 칩이 붙는 별개 엔티티다. 모바일 웹에서는 작성 UI가 열리지 않고, 설치 유도 모달이 "앱에서 코멘트와 기록을 남기고 공유"를 안내한다.
7. 소셜은 팔로우·피드(전체/팔로잉/내 활동)·알림으로 구성되고, 피드는 한 사용자의 여러 평가를 묶어서 보여준다.
8. 개인화: 로그인 시 랭킹·추천 카드가 평균 대신 **예상 별점**을 보여주고, 추천에 근거 문구가 붙는다. 취향분석은 데이터가 부족하면 빈 상태 문구를 보여준다.
9. `/review`는 미평가 작품을 연속으로 보여주는 **빠른 평가 스트림**이고, 평가 수에 따른 격려 문구가 붙는다.
10. 모든 페이지에 **앱 설치 유도 모달과 환영 광고 시트**가 반복 노출되며, 노출 시점이 일정하지 않다.
11. 사용자 하위 리소스가 `/users/{id}/{ratings|comments|decks|followers|followings|analysis}`로 정리돼 있고, 필터 상태는 URL 쿼리(`?content_type=books`)에 담긴다.
12. 로그인이 필요한 경로는 `sign_in?referer_url=<원래 경로>`로 보내 복귀 경로를 유지한다.

## 6. 게임 버전 적용 총괄

| 기능군 | 적용 | 요약 |
|---|---|---|
| 별점 평가 | 변형 적용 | 0.5 단위·정수 저장·즉시 저장은 유지. 명시적 취소 버튼과 키보드 조작 추가 |
| 평가 일자 | 변형 적용 | 시작일·엔딩일·100% 달성일 등 이벤트별 날짜로 확장 |
| 보고싶어요 / 보는 중 | 변형 적용 | 7단계 플레이 상태 + 진행도로 확장 |
| 코멘트(리뷰) | 변형 적용 | 웹에서 직접 작성. 평가와 별개 데이터 |
| 검색 | 그대로 적용 | 인기 검색어, 자동완성, 결과 탭, 결과 없음 문구 |
| 캘린더 | 변형 적용 | 평가 중심 → 플레이 이벤트 중심. 일별 상세, 월 선택, 월간 통계 유지 |
| 프로필·팔로우·피드·알림 | 그대로/변형 | 구조는 유지하고 게임 통계로 교체 |
| 취향분석 | 변형 적용 | 선호 장르·태그·플랫폼·플레이 시간. 장식적 시각화는 지양 |
| 좋아한 인물 | 변형 적용 | 좋아하는 게임회사 |
| 보관함 | 변형 적용 | 개인 게임 라이브러리 |
| 예상 별점·추천 | 제외(후속) | 데이터가 쌓인 뒤 검토 |
| 컬렉션 | 제외(후속) | MVP 범위 밖 |
| 매거진·이벤트·광고·앱 유도 | 제외 | 서비스 목표와 무관 |

## 7. 한계

- 코멘트 작성이 앱 전용인지는 **추정**이다. 웹에서 에디터가 열리지 않는 것까지만 확인했다.
- 설정, 월말결산, `재감상 기록하기`, 캘린더의 `+` 버튼 동작은 확인하지 못했다.
- 사용자 본인 계정 화면(프로필, 캘린더, 평가 목록, 피드)은 이메일·닉네임·시청 이력이 있어 **스크린샷을 저장소에 포함하지 않고** 구조만 문서화했다. 제3자 닉네임·아바타·코멘트가 보이는 화면도 같은 이유로 제외했다.
- 결과는 2026-11-10 시점의 모바일 웹 기준이며 이후 변경될 수 있다.
