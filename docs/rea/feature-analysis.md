# 기능 분석

각 기능은 요구사항의 표 형식을 따른다. 확인 수준 정의는 [overview](overview.md#2-확인-수준-정의), 화면 구조는 [page-analysis](page-analysis.md)를 본다. API 경로의 호스트는 `https://pedia.watcha.com`이다.

## F1. 별점 평가 (등록·수정·취소)

| 항목 | 설명 |
|---|---|
| 기능명 | 별점 평가 |
| 확인 여부 | 실제 확인(등록·반별·취소) / 부분 확인(다른 별점으로 값 변경은 실행하지 않음) |
| 사용자 목적 | 가장 적은 노력으로 작품에 대한 감상을 남긴다 |
| UI 구조 | 상세 화면의 별 5개(각 44×44px, 폭 220px 중앙 정렬). 미평가는 회색, 평가는 노란 채움이며 반별을 표현한다. 평가 후 `YYYY.MM.DD ·`, `수정`, `재감상 기록하기`, 코멘트 유도 버튼이 나타난다 |
| 인터랙션 | 별 탭 = 즉시 저장(확인 단계 없음). 별의 왼쪽 절반 = x.5, 오른쪽 절반 = 정수(4번째 별 왼쪽 탭 → 3.5). **같은 별을 다시 탭하면 취소**된다 |
| 핵심 데이터 | `POST /api/contents/{id}/ratings` 본문 `{"rating":7}` → 200 `{"metadata":{},"result":null}`. 취소는 같은 경로 `DELETE` → 200. 저장값 = 별점 × 2 (정수) |
| 게임 버전 적용 | 변형 적용 |
| 적용 이유 | 0.5 단위·정수 저장(1–10)·즉시 저장은 낮은 기록 비용 때문에 유지한다. 같은 별 재탭만으로 취소되는 숨은 동작은 접근성에 불리하므로 명시적 `평가 취소` 버튼과 키보드 조작을 추가한다 |

## F2. 본 날짜(평가 일자) 편집

| 항목 | 설명 |
|---|---|
| 기능명 | 본 날짜 변경 |
| 확인 여부 | 부분 확인(시트 열람까지. 날짜 선택·저장은 실행하지 않음) |
| 사용자 목적 | 실제로 본 날짜로 기록을 바로잡는다 |
| UI 구조 | `수정` → 바텀시트 "본 날짜 변경": 월 달력(예: 2026년 11월), 선택일 강조(기본 = 평가한 날), 닫기 버튼. 삭제 액션은 없다 |
| 인터랙션 | 평가 후에만 `수정`이 보인다. 시트는 오버레이 위에서 열린다 |
| 핵심 데이터 | 평가 일자(날짜). 저장 API는 미확인 |
| 게임 버전 적용 | 변형 적용 |
| 적용 이유 | 게임은 시작·엔딩·100% 달성이 서로 다른 날에 일어난다. 날짜를 이벤트별로 입력하게 확장하고 같은 날짜 선택 시트를 재사용한다 |

## F3. 보고싶어요 / F4. 보는 중

| 항목 | 설명 |
|---|---|
| 기능명 | 보고싶어요, 보는 중 |
| 확인 여부 | 실제 확인(켜기·끄기·새로고침 후 원복). 두 상태의 동시 활성 여부는 미확인 |
| 사용자 목적 | 평가와 무관하게 보관할 작품과 진행 중인 작품을 표시한다 |
| UI 구조 | 액션 행의 첫째·셋째 버튼(아이콘 + 라벨). 꺼짐 = 회색(`rgb(160,160,160)`), 켜짐 = 분홍(`rgb(255,47,110)`) |
| 인터랙션 | 탭 = 즉시 토글, 시트·확인 없음 |
| 핵심 데이터 | `POST`/`DELETE /api/contents/{id}/wish`, `POST`/`DELETE /api/contents/{id}/doing` (본문 `{}`) |
| 게임 버전 적용 | 변형 적용 |
| 적용 이유 | 왓챠는 2개 상태뿐이다. 게임은 관심 있음 / 플레이 예정 / 플레이 중 / 일시 중단 / 엔딩 완료 / 100% 달성 / 플레이 포기 7단계와 진행도가 필요하다. "평가와 독립"이라는 구조는 그대로 유지한다 |

## F5. 코멘트 작성

| 항목 | 설명 |
|---|---|
| 기능명 | 코멘트 작성 |
| 확인 여부 | 부분 확인 |
| 사용자 목적 | 평가에 글로 감상을 더한다 |
| UI 구조 | 진입점 2곳: 액션 행의 `코멘트`, 평가 직후의 유도 버튼("좋은 평가네요. {닉네임}님의 생각을 글로 남겨보세요."). 유도 문구가 별점에 따라 바뀌는지는 한 값만 봐서 **미확인** |
| 인터랙션 | 두 진입점 모두 클릭해도 화면 이동·다이얼로그·입력창·쓰기 API 호출이 없었다. 설치 유도 모달이 "앱에서 코멘트와 기록을 남기고 공유해보세요!"라고 안내하는 점과 일치하지만, **앱 전용이라는 결론은 추정**이다 |
| 핵심 데이터 | 미확인(본문 길이 제한, 스포일러 표시, 공개 범위, 평가 필수 여부 모두 미확인) |
| 게임 버전 적용 | 변형 적용 |
| 적용 이유 | SavePoint는 모바일 웹이 유일한 클라이언트이므로 웹에서 직접 작성할 수 있어야 한다. 평가 필수 여부는 REA로 정할 수 없어 [feature-specification](../product/feature-specification.md)에서 "평가와 독립"으로 결정한다 |

## F6. 코멘트 목록·상세·반응

| 항목 | 설명 |
|---|---|
| 기능명 | 코멘트 목록·상세·좋아요·댓글 |
| 확인 여부 | 실제 확인(상세·카드), 부분 확인(목록 전체 화면) |
| 사용자 목적 | 다른 사람의 감상을 읽고 반응한다 |
| UI 구조 | 상세 화면 `코멘트 100+` 섹션의 카드: 작성자·날짜(`YY.MM.DD`)·별점 숫자·본문 링크·"OO님 외 N명이 좋아해요"·👍 수·댓글·`…`. 코멘트 상세: 별점 칩(`★ 5.0`)·포스터 썸네일·댓글 입력·"댓글 N개"·정렬 `좋아요 순`. 비로그인은 카드가 블러 처리되고 로그인 유도 |
| 인터랙션 | `더보기` → 전체 목록(로그인 필요). 카드 → 코멘트 상세. 좋아요는 별도 버튼 |
| 핵심 데이터 | `GET /api/contents/{id}/comments?filter=all\|friends&order=popular`, `GET /api/comments/{id}/replies?replies_size=9`, `GET /api/contents/{id}/possessed_comments`(내 코멘트로 추정, 미확인) |
| 게임 버전 적용 | 그대로 적용 (댓글은 후속) |
| 적용 이유 | 점수 + 글 + 좋아요 구조가 검증돼 있다. `전체`/`친구` 필터와 인기순 정렬도 유지한다 |

## F11. 캘린더

| 항목 | 설명 |
|---|---|
| 기능명 | 월간 캘린더 / 일별 상세 / 월말결산 |
| 확인 여부 | 실제 확인(월간·일별·월 선택 시트·필터), 부분 확인(`+` 버튼, 월말결산 화면은 미확인) |
| 사용자 목적 | 한 달 동안 무엇을 봤는지 한눈에 확인한다 |
| UI 구조 | [page-analysis §7](page-analysis.md#7-캘린더--실제-확인-로그인-필요) 참고. 평가한 작품 포스터가 날짜 칸에 놓이고 개수 배지가 붙는다 |
| 인터랙션 | 월 제목 → 월 선택 시트(`완료`). 날짜 탭 → 일별 상세 페이지(`/calendar/detail/.../D`). 도메인 칩은 URL 쿼리로 반영된다 |
| 핵심 데이터 | `GET /api/users/{id}/ratings/{YYYY}/{M}`, `GET /api/users/{id}/user_month_report/{YYYY}/{M}/ratings`. 날짜 칸의 기준이 "평가한 날"인지 "본 날짜"인지는 **미확인**(본 날짜를 바꿔보지 않음) |
| 게임 버전 적용 | 변형 적용 |
| 적용 이유 | 핵심 차별화 기능과 구조가 같다. 평가 일자 대신 플레이 시작·엔딩·100%·리뷰·평가 이벤트를 올리고, 이벤트 종류는 색뿐 아니라 아이콘·레이블로도 구분한다. 커버 이미지는 칸을 가리지 않도록 작은 썸네일로만 쓰고 일별 상세에서 크게 보여준다 |

## F14. 피드·알림

| 항목 | 설명 |
|---|---|
| 기능명 | 소셜 피드, 알림 |

| 게임 버전 적용 | 변형 적용 |

## 요구사항 질문에 대한 답

### 3.2 평가 시스템

| 질문 | 답 | 수준 |
|---|---|---|
| 평가 UI 형태 | 별 5개, 영역 탭 | 실제 확인 |
| 점수 범위·단위 | 0.5–5.0, 0.5 단위(코멘트 카드의 3.5·4.5와 분포 축에서 확인). 저장값은 3.5 → 7만 확인했고 정수 1–10 범위는 추정 | 부분 확인 |
| 등록·수정 | 탭 즉시 저장. 다른 별로 수정 시 동작은 미실행 | 부분 확인 |
| 취소 | 같은 별 재탭 → `DELETE` | 실제 확인 |
| 미평가 vs 평가 UI | 회색 → 노란 별, 날짜·`수정`·`재감상 기록하기`·코멘트 유도 버튼 노출 | 실제 확인 |
| 평가 후 상세 변화 | 위와 같음. 평균 별점·평가 수 갱신 여부는 미확인 | 부분 확인 |
| 프로필 반영 | 평가 수, 캘린더, 취향분석에 반영. 취소하면 월 평가 수가 원복됨 | 실제 확인 |
| 평가와 리뷰 | 별개 엔티티. 평가 후 코멘트 작성을 유도하고, 코멘트 카드에 점수가 표시됨 | 부분 확인 |
| 평가와 좋아요 | 별개. 액션 행에 콘텐츠 `좋아요`는 없고 `보고싶어요`가 있다. 좋아요는 코멘트·인물에만 있음 | 실제 확인 |

### 3.3 리뷰 시스템

| 질문 | 답 | 수준 |
|---|---|---|
| 작성 진입점 | 액션 행 `코멘트`, 평가 후 유도 버튼 | 실제 확인 |
| 작성 UI | 웹에서 열리지 않음 | 부분 확인 |
| 평가 필수 여부 | 알 수 없음 | 미확인 |
| 수정·삭제 | 카드의 `…` 메뉴가 있으나 열어보지 않음 | 미확인 |
| 공개 범위 | 알 수 없음 | 미확인 |
| 정렬 | 목록 `order=popular`, 내 코멘트 `작성 순` 콤보, 댓글 `좋아요 순` | 실제 확인(값 목록은 미확인) |
| 좋아요 | 👍 + "OO님 외 N명이 좋아해요" | 실제 확인 |
| 작성일 표시 | `YY.MM.DD`(예: `25.08.26`), 피드·알림은 상대 시간 | 실제 확인 |
